RiceConnect — Merged Migration Plan

Combines the competition-scoped operational plan (riceconnect-migration-plan.html) with the technical depth of the full blueprint (MIGRATION_PLAN.html). Plan B's scope cuts and calendar are the authority; Plan A's code patterns, folder structure, and component maps fill the gaps.

From: rice-connect-v2 (Laravel 12 / Inertia / React / Render) To: Next.js + Supabase + Prisma + Vercel 11 dev days before capacity-building block

TL;DR

  • This is a port, not a rebuild. Karl's Laravel repo is a working spec of the domain model. Speed advantage assumed.
  • Sep 9 – Sep 20 is the entire dev runway. 11 days to port: Farmer + Miller + Ledger + Auth + Market Price Board. Retailer, Driver, Analytics deferred.
  • The ledger is the load-bearing piece. A sloppy port costs someone real money. Prisma $transaction + atomic increment/decrement replaces Laravel's DB::transaction.
  • Auth enforcement: app-layer role check in Next.js middleware + API routes. Not RLS — Prisma bypasses RLS, making it a false sense of security.
  • Notifications: synchronous send in API routes. No queue, no DB triggers. Four notification types at pilot scale don't need infrastructure.
  • Branch convention: main + development, matching LikasLens. Vercel builds gated to these branches.

2Scope Cut — What Ports Now vs. What Waits

Porting everything is a 4–6 week job. You have 11 days. The cut below keeps everything the pitch and pilot need; everything the rubric doesn't ask for yet is deferred.

3.2 CHECK Constraints (Raw SQL Migration)

Prisma doesn't express CHECK constraints natively. Add via a raw SQL migration step:

-- migrations/20260909_add_check_constraints.sql

-- Ledger: amount must be positive
ALTER TABLE ledger_entries
  ADD CONSTRAINT ledger_amount_positive CHECK (amount > 0);

-- Bookings: weight and sacks must be non-negative
ALTER TABLE bookings
  ADD CONSTRAINT bookings_non_negative
  CHECK (total_weight_kg >= 0 AND estimated_sacks >= 0);

6Page Conversion Pattern

Every Inertia page follows the same conversion: server-side data fetch in a Server Component, interactive parts extracted to Client Components.

6.1 Before (Inertia + React)

// resources/js/Pages/Farmer/HarvestIndex.jsx
import AuthenticatedLayout from '@/Layouts/AuthenticatedLayout'
import { router } from '@inertiajs/react'

export default function HarvestIndex({ auth, batches }) {
  return (
    <AuthenticatedLayout header={<h2>Harvests</h2>}>
      {batches.map(batch => (
        <div key={batch.id}>{batch.rice_variety}</div>
      ))}
    </AuthenticatedLayout>
  )
}

6.2 After (Next.js Server Component)

// src/app/(protected)/farmer/harvest/page.tsx
import { prisma } from '@/lib/prisma'
import { redirect } from 'next/navigation'
import HarvestList from '@/components/modules/farmers/HarvestList'

export default async function HarvestPage() {
  const batches = await prisma.harvestBatch.findMany({
    where: { hiddenFromFarmer: false },
    orderBy: { createdAt: 'desc' },
    include: { farmer: true, interests: { include: { miller: true } } },
  })

  return <HarvestList batches={batches} />
}

// src/components/modules/farmers/HarvestList.tsx (Client Component)
'use client'

    </div>
  )

7Auth & Role Enforcement

Supabase Auth handles identity. A role column on the user drives authorization, checked in Next.js middleware for page routes and again in each API route handler. This mirrors Karl's RoleMiddleware — single role-string check per route group.

Do NOT use RLS as the enforcement layer

Prisma typically connects with a service-role that bypasses RLS. RLS policies that Prisma silently bypasses are worse than no RLS — they look like protection and aren't.

7.1 Next.js Middleware (Auth Guard)

// src/middleware.ts
import { createServerClient } from '@supabase/ssr'
import { NextResponse, type NextRequest } from 'next/server'

const roleDashboard: Record<string, string> = {
  farmer: '/farmer/harvest',
  miller: '/miller/marketplace',
  admin:  '/admin/dashboard',
}

export async function middleware(request: NextRequest) {
  let supabaseResponse = NextResponse.next({ request })
  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,
    { cookies: { getAll: () => request.cookies.getAll(), setAll: () => {} } }
  )

  const { data: { user } } = await supabase.auth.getUser()

  // Protected routes
  if (request.nextUrl.pathname.startsWith('/(protected)')) {
    if (!user) {
      return NextResponse.redirect(new URL('/login', request.url))
    }
  }

  // Guest routes → redirect to dashboard if logged in
  if (request.nextUrl.pathname.startsWith('/(auth)') && user) {
    const { data: profile } = await supabase
      .from('users').select('role').eq('id', user.id).single()
    return NextResponse.redirect(
      new URL(roleDashboard[profile?.role] || '/dashboard', request.url)
    )
  }

  return supabaseResponse
}

export const config = {
  matcher: ['/(auth)/:path*', '/(protected)/:path*']
}

8PaymentService → Prisma Transaction

The invariant: wallet.balance == sum(credits) - sum(debits), held by construction. The Laravel version uses DB::transaction + increment/decrement. The Prisma version uses prisma.$transaction() with atomic operations.

8.1 Core Payment Logic

// src/lib/payment.ts
import { prisma } from '@/lib/prisma'

type TransferOptions = {
  checkBalance?: boolean
}

export async function transfer(
  fromUserId: string,
  toUserId: string,
  amount: number,
  debitDescription: string,
  creditDescription: string,
  referenceType?: string,
  referenceId?: number,
  options: TransferOptions = {}
): Promise<boolean> {
  if (amount <= 0) throw new Error('Payment amount must be greater than zero.')
  if (fromUserId === toUserId) throw new Error('Cannot transfer money to the same user.')

  return prisma.$transaction(async (tx) => {
    // Idempotency check
    if (referenceType && referenceId) {
      const existing = await tx.ledgerEntry.findFirst({
        where: {
          userId: fromUserId,
          type: 'debit',
          referenceType,
          referenceId,
        },
      })
      if (existing) return false
    }

    // Ensure wallets exist
    await tx.wallet.upsert({
      where: { userId: fromUserId },
      create: { userId: fromUserId, balance: 0 },
      update: {},
    })
    await tx.wallet.upsert({
      where: { userId: toUserId },
      create: { userId: toUserId, balance: 0 },
      update: {},
    })

    // Check balance if required
    if (options.checkBalance) {
      const senderWallet = await tx.wallet.findUnique({
        where: { userId: fromUserId },
      })
      if (senderWallet && senderWallet.balance.lessThan(amount)) {
        throw new Error('Insufficient funds.')
      }
    }

    // Atomic debit + credit
    await tx.wallet.update({
      where: { userId: fromUserId },
      data: { balance: { decrement: amount } },
    })
    await tx.wallet.update({
      where: { userId: toUserId },
      data: { balance: { increment: amount } },
    })

    // Write ledger entries
    await tx.ledgerEntry.createMany({
      data: [
        {
          userId: fromUserId,
          amount,
          type: 'debit',
          referenceType: referenceType || null,
          referenceId: referenceId || null,
          description: debitDescription,
        },
        {
          userId: toUserId,
          amount,
          type: 'credit',
          referenceType: referenceType || null,
          referenceId: referenceId || null,
          description: creditDescription,
        },
      ],
    })

    return true
  })
}

function bfs(start: string, end: string): number {
  if (!iloiloNeighbors[start] || !iloiloNeighbors[end]) return 3
  const queue: [string, number][] = [[start, 0]]
  const visited = new Set([start])
  while (queue.length) {
    const [current, dist] = queue.shift()!
    if (current === end) return dist
    for (const neighbor of iloiloNeighbors[current] || []) {
      if (!visited.has(neighbor)) {
        visited.add(neighbor)
        queue.push([neighbor, dist + 1])
      }
    }
  }
  return 3
}

export function calculateDeliveryFee(
  start: string,
  end: string,
  baseFee: number,
  extraFeePerMunicipality: number
): number {
  if (start === end) return 0
  const jumps = bfs(start, end) || 1
  return baseFee + Math.floor((jumps - 1) / 2) * extraFeePerMunicipality
}

10Booking State Machine

Port the strict forward-only state machine from BookingController.php. Used by both palay pickup and rice delivery flows.

// src/app/api/bookings/[id]/status/route.ts
import { prisma } from '@/lib/prisma'
import { NextRequest, NextResponse } from 'next/server'

const validTransitions: Record<string, string> = {
  pending:    'assigned',
  assigned:   'at_pickup',
  at_pickup:  'in_transit',
  in_transit: 'delivered',
}

export async function POST(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  const { status: newStatus } = await request.json()

  const booking = await prisma.booking.findUnique({
    where: { id: Number(params.id) },
    include: { harvestBatch: true },
  })

  if (!booking) {
    return NextResponse.json({ error: 'Booking not found' }, { status: 404 })
  }

  // Validate transition
  if (validTransitions[booking.status] !== newStatus) {
    return NextResponse.json(
      { error: `Cannot transition from ${booking.status} to ${newStatus}` },
      { status: 400 }
    )
  }

  // Money-gate for palay
  if (
    booking.harvestBatchId &&
    newStatus === 'in_transit' &&
    booking.harvestBatch?.deliveryStatus !== 'Payment Authorized'
  ) {
    return NextResponse.json(
      { error: 'Miller must authorize payment before transit' },
      { status: 400 }
    )
  }

  // Update booking + sync delivery status on parent entity
  await prisma.$transaction(async (tx) => {
    await tx.booking.update({
      where: { id: booking.id },
      data: { status: newStatus },
    })

    const deliveryStatusMap: Record<string, string> = {
      assigned:   'Pending',
      at_pickup:  'Pending',
      in_transit: 'In Transit',
      delivered:  'Delivered',
    }

    if (booking.harvestBatchId) {
      const update: Record<string, any> = {
        deliveryStatus: deliveryStatusMap[newStatus] || 'Pending',
      }
      if (newStatus === 'in_transit') update.status = 'in_transit'
      if (newStatus === 'delivered') {
        update.status = 'received'
        update.deliveryStatus = 'Received'
      }
      await tx.harvestBatch.update({
        where: { id: booking.harvestBatchId },
        data: update,
      })
    }
  })

  return NextResponse.json({ success: true })
}

10.1 Accept Job (Driver Claims Booking)

// src/app/api/bookings/[id]/accept/route.ts
import { prisma } from '@/lib/prisma'
import { NextRequest, NextResponse } from 'next/server'

export async function POST(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  const { driverId } = await request.json()

  await prisma.$transaction(async (tx) => {
    const booking = await tx.booking.findUnique({
      where: { id: Number(params.id) },
    })

    if (!booking || booking.status !== 'pending') {
      throw new Error('Job taken or unavailable.')
    }

    await tx.booking.update({
      where: { id: booking.id },
      data: { driverId, status: 'assigned' },
    })

    // Sync driver_id back to HarvestBatch
    if (booking.harvestBatchId) {
      await tx.harvestBatch.update({
        where: { id: booking.harvestBatchId },
        data: { driverId, deliveryStatus: 'Pending' },
      })
    }
  })

  return NextResponse.json({ success: true })
}
